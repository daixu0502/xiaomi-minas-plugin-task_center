# 定时任务 · 小米智能存储插件

版本 **1.0.0**。在手机 APP 和电脑客户端内配置 NAS 定时任务、查看执行结果。无需额外 Web 端口，不依赖 Docker 部署插件本身。此版新增时间计划、前置条件/成功联动、安全清理与失败重试。

## 首次使用

安装后打开「定时任务 → 任务」，编辑预置任务，选择容器或填写脚本路径，检查计划时间并保存，再点击「启用」。**所有预置任务默认停用，保存修改也会自动停用，必须再次手动确认启用。**「立即执行」只执行一次，不会启用计划。

模板库提供 10 个默认停用模板。全新安装会预置任务；升级保留已有任务，不补回删除过的模板、不改变任务启用状态。新增模板可从「模板」页手动添加。

| 模板 | 默认计划 |
| --- | --- |
| 重启整台 NAS | 周日 04:30 |
| 启动已有容器 | 每天 08:00 |
| 停止已有容器 | 每天 23:30 |
| 重启已有容器 | 周日 04:00 |
| 从本地镜像创建/启动容器 | 每天 08:00 |
| 等待存储池后启动容器 | 开机延迟 120 秒 |
| 执行用户脚本 | 每天 02:00 |
| 清理过期日志 | 周日 03:00，保留 30 天 |
| 清理临时文件 | 周日 03:00，保留 7 天 |
| 清理指定回收站旧文件 | 周日 03:00，保留 30 天 |

「模板」页可以重复创建任务；「记录」页显示运行结果和命令输出。脚本通过 `/bin/sh` 以安装插件的 NAS 用户执行，不授予 root。需要 Bash 的脚本可用一个 sh 包装脚本调用 Bash。

## 时间计划

- 每天、每周多选、工作日（周一至周五，不识别法定节假日）、周末。
- 每月指定日期：该月没有此日则跳过，例如 31 日不会自动挪到月底。
- 指定日期/时间，仅一次：错过不补跑，触发后自动停用；启用时拒绝过去的时间。
- 固定分钟间隔：可限制每天的执行时间窗口，起止分钟包含在内，暂不跨午夜；跨午夜请拆成两个任务。
- 高级 Cron：五段「分 时 日 月 周」，支持 `*`、逗号、数字范围与 `/` 步长。周日为 0 或 7，不支持秒段、英文月份、`@reboot`、`L/W/#` 等扩展。日期和星期均限定时采用传统 Cron 的“或”规则。
- 开机后延迟、前置任务成功后。

编辑页可以预览未来 5 次时间（NAS 时区，尚未启用也可预览）。月计划/Cron 最远搜索未来 8 年，预览不保证届时前置条件一定满足。所有触发精度为分钟，不是秒级定时器。

## 前置条件与任务联动

执行前可以检查存储池挂载、Docker 引擎就绪，以及最多 8 个目录是否存在且当前用户有读取/进入权限。目录只检查可访问性，不代替备份完整性或硬盘健康检查。普通计划/联动条件不满足则记录跳过；开机任务从延迟到期起最多等待 30 分钟。

选择「前置任务成功后」，指定同一用户的一个父任务：只有启用后的新执行结果才会触发，每分钟检查；父任务失败、超时或跳过时记录跳过，若正在等待自动重试则等最终结果。父任务手动执行也能触发；不会补跑启用前已经创建的历史执行。每条父任务完成记录最多触发一次，受最近 100 条执行历史保留范围限制。禁止自引用、循环依赖，也不能删除仍被其他任务引用的父任务。

例如：任务 A 在开机后检查存储池、目录和 Docker，启动某容器；任务 B 选择“A 成功后”，再启动另一个容器。**「立即执行」绕过日期和父任务触发，但仍检查存储池/目录/Docker 条件。**本功能不阻止 Docker 自己的自动重启策略，若需要由插件安排开机顺序，请自行调整对应容器策略。

## 失败重试

默认不启用。支持在编辑页设置 **失败/超时后每隔 5 分钟、最多重试 3 次**；可调整间隔 1–1440 分钟和重试 1–3 次，次数不包含首次执行。首次加重试最多执行 4 次，不与同任务的普通计划并发。等待重试期间普通计划不另开执行，后续成功就停止重试。

仅支持「启动已有容器」和「执行用户脚本」。NAS 重启、容器停止/重启、创建容器、清理不开放自动重试。脚本可能已经部分执行，启用前须确认其能安全重复执行。条件不满足或设备重启中断不自动重试。

任务卡片显示下次重试时间，可单独「取消重试」。停用任务、编辑保存、删除、停用调度器会取消等待中的重试；不终止已经执行中的命令。每次尝试独立记录，显示重试次数和输出。

## 安全清理

清理模板不填写默认目标目录，必须手动指定。流程：**保存为停用 → 预览清理 → 检查范围、数量、容量和文件示例 → 再确认启用/立即执行**。预览令牌 10 分钟内有效；修改任务使确认失效。

- 只允许当前用户 `/nas/pool0/<用户>/data/` 下的明确子目录，或 `/home/<用户>/plugin/<插件>/var/` 目录及其子目录。禁止文件区根目录、其他用户目录、系统目录和系统 Docker 数据目录。路径别名解析后仍须处于允许范围。
- 日志匹配 `*.log`、`*.log.[0-9]*`、`*.log.gz`；临时文件仅匹配 `*.tmp`、`*.temp`，不自动清理 `.part` 下载文件。
- 回收站必须明确选中名为 `.recycle`、`#recycle`、`@recycle`、`$RECYCLE.BIN`、`recycle`、`Recycle` 或 `回收站` 的目录，不自动搜索/推断回收站。
- 以当前用户身份运行，只清理本人拥有、单硬链接的普通文件。按最后修改时间判断保留天数，不按放入回收站的时间。不会删除目录、跟随符号链接或跨设备扫描。
- 默认每次最多 1000 个文件、1024 MiB。可调上限为 10000 个、10240 MiB；预扫描超限时整次拒绝，不先删一部分。扫描超过 50000 个条目、深度 32 或 8 秒时拒绝，需缩小目录范围。
- 每次执行重新扫描，之后新达到保留天数的文件也在已授权的规则内。执行前核对目录设备号/inode；目录替换或挂载变化后必须重新预览确认。逐文件重新核对身份、大小、修改时间等；扫描后变化的文件跳过。
- **永久删除，不能撤销，不会移入回收站。**文件系统快照等可能导致实际空间未立即释放；运行途中发生权限错误/超时可能部分完成，会记录失败，不自动重试。重要文件请先备份。

## 安装与卸载

保留 `manage.sh` 和整个 `payload/` 目录，在 NAS 本机以 root 执行，或在 WSL/Linux 中通过 root SSH 安装：

```bash
bash manage.sh                         # 交互选择安装/卸载、设备和用户
bash manage.sh install                 # 安装/更新
bash manage.sh uninstall               # 卸载选定用户
bash manage.sh install --list-users    # 只扫描用户
bash manage.sh install --dry-run       # 只校验并显示计划
```

远程非交互示例（请替换示例 IP 和用户）：

```bash
bash manage.sh install --ip 192.168.31.100 --users u123456789
bash manage.sh uninstall --ip 192.168.31.100 --users u123456789 --yes
```

支持逗号分隔的多用户及 `--all-users`。未填写远程 IP 时交互输入，NAS 本机自动直装。需要系统已有 Python 3、jq、sudo、crond、plugincenter 等组件；不会自动安装系统依赖。具体参数见 `bash manage.sh install --help`。

用户之间的计划和日志隔离。与 Docker Manager 共用无监听端口的公共权限组件 1.x；任意一个插件均可独立安装，自带所需组件，不要求先装另一个。Docker 和 NAS 重启是全局操作，不是用户专属资源；只应向可信管理员开放插件。

## 调度与安全边界

- 使用 **NAS 系统时区**，每分钟检查一次。
- 分钟间隔按 Unix 时间的分钟边界计算，不从启用时刻起算；普通错过的计划不补跑。
- 开机计划仅在启用后的下一次启动生效。勾选存储池检查时，等待 `/nas/pool0` 成为挂载点，最长等待延迟时间之后 30 分钟；普通计划未挂载则跳过。此检查不替代磁盘健康检测。
- 若要通过本插件控制容器开机顺序，需自行取消对应容器的 Docker 自动重启策略，否则 Docker 仍可能提前启动它。插件不擅自修改现有策略。
- 同一任务不并发执行；执行中不能修改、删除、卸载。两插件的 Docker 写操作共用一把全局锁，升级/批量操作期间仍可查询状态，冲突写操作会明确返回忙；任务仅在配置允许时按失败重试规则重试。SSH、其他插件和 Docker 自身的操作不受这把锁控制。
- 超时 10–3600 秒。脚本输出最多 64 KiB；完成后清理同进程组子进程，不适合启动长期后台服务。Docker 超时只代表客户端等待超时，请核查引擎侧实际状态。
- 重启任务调用 `shutdown -r +1`，记录「已请求重启」而非声称重启完成。取消计划或卸载插件不会撤销已提交的重启请求；必要时管理员可在 SSH 执行 `shutdown -c`。
- 镜像模板仅使用 **本地镜像**，创建桥接网络、无端口映射、无目录挂载、无特权、`--restart no` 的容器。不自动拉取或升级镜像。同名容器只复用该任务创建且镜像相同的容器。复杂服务请先在 Docker Manager 配置，再使用「启动已有容器」。
- 最多 100 个任务；保留最近 100 条已完成记录及正在执行/等待重试的记录。

## 安装位置

- `/home/<用户>/plugin/taskcenter/`：INFO 元信息、控制脚本及源目录链接。
- `/nas/pool0/<用户>/plugin/pluginsrc/taskcenter/`：界面、CGI、注册脚本。
- `/data/.minas-privileged/minas-helper`：两个插件共用的 root 权限入口，API v1。
- 同目录的 `privileged_runtime.py`、`docker-manager-helper`、`task-center-helper`、`task_schedule.py`、`task_maintenance.py`：公共执行接口、Docker 和调度模块。
- `/data/.minas-privileged/registry.json`：root 保管的用户/模块授权及版本登记。
- `/data/.minas-privileged/users/<用户>/`：root 保管的任务和日志。涉及 NAS 重启等提权计划，不能放到普通用户可修改的目录直接信任执行。
- `/etc/sudoers.d/taskcenter-<用户>`：仅授权 `minas-helper taskcenter`，不带通配符；助手核验真实 sudo 用户，拒绝内部调度参数及跨用户请求。
- `/etc/cron.d/minas-privileged`：每分钟调用一次公共调度入口。
- `/data/plugin/<用户>.list`：插件注册信息；`INFO` 由安装器动态生成。

更新保留任务、记录及调度器启用状态。组件升级/移除先备份到 `/data/.minas-privileged-backups/<时间>/`，插件元信息另备份到 `/data/.taskcenter-backups/<用户>/`。卸载只移除所选用户的 taskcenter 授权和调度数据；仍有任何用户使用 Docker Manager 或定时任务时保留公共组件，最后一个引用移除后清理公共执行文件和 cron（保留受保护的登记/锁目录及备份）。**不删除任务引用的容器、镜像、脚本和用户文件。备份可能包含私有路径或日志，请勿公开上传。**

从 0.1.0 升级时，将所选用户的任务、日志和启用状态迁移到 `/data/.minas-privileged/users/`，避免在可由普通用户写入的 `/data/plugin/` 父目录下执行 root 代码。旧数据副本停用后保留，写入 `MIGRATED_TO_COMMON` 标记，重新安装不自动复活旧任务。其他尚未升级的用户保留旧调度，需分别升级。

公共组件不提供任意 root shell 接口，不开放 TCP 端口，也不修改 docker.sock 权限。普通用户脚本及清理仍降权执行。同一 NAS 账户的两个插件共享系统 UID，安装两者意味着该账户获得两者授权的并集，并非强插件沙箱；完整 Docker 管理（尤其宿主机目录挂载）属于接近 root 的高信任能力。安装器拒绝权限模块降级和不兼容的 API 主版本。不得使用旧安装器覆盖新版插件。

手机 Android/iOS 的深浅色跟随 WebView 提供的系统主题信号，电脑端固定雾蓝灰。若宿主 APP 未传递主题信号，插件无法仅凭系统设置判断；请先重新进入插件。CGI 静态路由包含 `palette.css`，避免返回 HTML 导致样式失效。

## 开发验证

`python3 tests/test_helper.py` 在 Linux 临时目录运行隔离测试；Docker、重启和后台任务启动均被模拟，文件清理仅对测试新建的临时样本运行，不操作实际服务或用户文件。`node --check payload/ui/app.js` 检查前端语法，`node tests/preview.cjs` 使用 Playwright 与模拟 API 验证桌面/手机布局、计划表单、清理确认流程。此版尚无通知推送、任意 root 命令或秒级任务。
